# TopBearing — пакет оновлення 2026-08-24

Цей пакет замінює серверну логіку, Jinja-шаблони та CSS/JS для запитаного оновлення магазину.

## Що реалізовано

- з форми входу прибрано пояснення про «один вхід»;
- клієнтське «Забули пароль?» з одноразовим timed-token; у production лист іде через SMTP;
- зміна пароля в акаунті, у тому числі для адміністратора;
- замовлення мають статуси `Нове`, `Оброблено`, `Відправлено`, `Скасовано`, окремий статус оплати та ТТН;
- перероблена форма товару з обов'язковими полями залежно від категорії;
- бренд — довідник: можна ввести існуючий або новий, новий створиться автоматично;
- для клієнта точна складська кількість не показується;
- до 8 фото товару за одне збереження;
- пошук розмірів `25-54-10`, `25x54x10`, `25×54×10` для підшипників і сальників;
- категорії `Змащення` й `Аксесуари`;
- checkout для Нової пошти, Укрпошти й самовивозу;
- онлайн-оплата через Monobank Internet Acquiring;
- єдиний глобальний мінімальний ліміт для післяплати; per-product/per-category правила прибрані з UI та нової ORM-схеми;
- телефон, email, адреса, Telegram та строк відправки редагуються в адмінці;
- строк «1–3 робочих дні» показується на товарі, в кошику, checkout, контактах та після оформлення;
- мобільне hamburger-меню, окремий кошик, sticky-кнопка фільтрів, скрольне меню;
- «Обране» працює через `localStorage`, тому не потребує авторизації;
- картки товарів на вузькому екрані стають горизонтальними, широкими та невисокими.

## Рішення по «Опису» та «Артикулу»

**Артикул потрібен, але не як обов'язкове поле.** Є два різні поля:

1. `manufacturer_code` — артикул/позначення виробника (наприклад `6319 C4`). Це те, що має сенс показувати покупцеві та шукати.
2. `sku` — внутрішній стабільний код TopBearing. Якщо адміністратор його не введе, він генерується автоматично. Він потрібен для БД, імпорту, замовлень та майбутньої синхронізації з обліковою системою.

**Опис:** для підшипників, ременів та сальників він необов'язковий, бо основна інформація структурована в характеристиках. Для змащень та аксесуарів змістовний опис обов'язковий.

## Порядок оновлення

1. Зробіть backup БД і папки проєкту.
2. Замініть файли з пакета.
3. Встановіть/оновіть залежності:

```bash
python -m pip install -r requirements.txt
```

4. Збережіть свій `.env`, але додайте в нього потрібні нові змінні з `.env.example`.
5. Запустіть недеструктивне оновлення схеми:

```bash
python scripts/migrate_20260824.py
```

6. Якщо потрібно створити категорії/першого admin у новій БД:

```bash
python seed.py
```

`seed.py` **не змінює пароль уже існуючого адміністратора**, навіть якщо `ADMIN_PASSWORD` у `.env` інший. Після входу адміністратор змінює пароль у `Акаунт → Змінити пароль`.

7. Запуск:

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## Monobank: онлайн-оплата

У `.env` додайте merchant token:

```env
MONOBANK_TOKEN=...
PUBLIC_BASE_URL=https://your-domain.ua
```

`PUBLIC_BASE_URL` має бути реальним HTTPS-доменом, щоб Monobank міг викликати webhook. Token залишається тільки на сервері й не потрапляє в HTML/JS.

Якщо `MONOBANK_TOKEN` не заданий, пункт онлайн-оплати автоматично не показується; рахунок і післяплата продовжують працювати відповідно до налаштувань.

## Відновлення пароля

Для production налаштуйте SMTP у `.env`. Без SMTP в development-режимі сайт покаже локальне посилання відновлення на самій сторінці — це зроблено лише для тестування.

## Стара логіка оплати

Новий код не має per-product/per-category опцій передоплати. При оновленні існуючої БД старі колонки спочатку залишаються фізично, щоб не робити ризиковану destructive migration під час першого запуску. Після backup і перевірки нового сайту їх можна видалити:

```bash
python scripts/drop_legacy_payment_columns.py --yes
```

Цей cleanup необов'язковий для роботи сайту.
