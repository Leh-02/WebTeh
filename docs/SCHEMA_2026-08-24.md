# TopBearing — схема після оновлення 2026-08-24

Основна ідея: спільні комерційні поля зберігаються в `products`, а технічні характеристики — у таблиці відповідної категорії.

## Основні таблиці

- `users` — клієнти й адміністратори; email, hash пароля, роль, ПІБ, телефон.
- `categories` — `bearings`, `belts`, `seals`, `lubricants`, `accessories`.
- `brands` — нормалізований довідник брендів.
- `products` — внутрішній SKU, артикул виробника, назва, категорія, бренд, ціна, опис, наявність.
- `product_images` — до 8 фото на товар; перше є головним.
- `bearing_specs`, `belt_specs`, `seal_specs`, `lubricant_specs` — технічні характеристики.
- `orders`, `order_items` — замовлення та snapshot товарів на момент замовлення.
- `store_settings` — глобальний ліміт післяплати, способи оплати, контакти, повідомлення про відправку.

## Наявність

`stock_is_tracked = true` означає, що адмін веде точний залишок у `stock_qty`. Покупцеві число не віддається: він бачить лише `В наявності` або `Немає в наявності`.

Якщо точний склад не ведеться, використовується `availability_status`: `in_stock`, `out_of_stock` або `on_order`.

## Оплата

Правила передоплати для окремого товару або категорії більше не використовуються. Глобальний `store_settings.cod_min_total` задає мінімальну суму, від якої доступна післяплата. Нижче ліміту checkout показує лише передоплатні методи, які увімкнені.

У старій БД legacy-колонки можуть тимчасово залишитися для безпечного оновлення, але новий ORM їх не використовує. Після backup їх можна видалити окремим cleanup-скриптом.
